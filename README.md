# Digital Payments Trend Analyzer

An end-to-end project that analyzes transaction-level digital payments data, identifies
trends and peak seasons, predicts future payment volumes, and predicts the most preferred
payment channel (Mobile/Digital vs Card/Bank) — delivered as a Jupyter notebook (analysis +
model training) and an interactive Dash dashboard.

> **Note on the dataset:** the original project brief (Section E, PO-01) describes a Tanzania
> mobile-money monthly summary dataset (`mpesa_vol_mn`, `tigopesa_vol_mn`, etc.). The CSV
> actually provided (`Digital_Payments_Data.csv`) is a different, transaction-level dataset
> (10,057 rows, GBP amounts, 2024–2025, generic sectors/stores). This project was built around
> the real data supplied. The "Mobile/Digital vs Card/Bank" split (built from `Payment_Method`)
> stands in for the M-Pesa/PesaLink/TISS-style channel comparison from the brief.

## Setup (PyCharm)

1. **Open the project folder** `DigitalPaymentsAnalyzer` in PyCharm (`File → Open`).
2. **Create/select a Python interpreter** (Conda env recommended, matching your usual setup):
   `File → Settings → Project → Python Interpreter → Add Interpreter → Conda Environment`.
3. **Install dependencies** — open the PyCharm terminal and run:
   ```bash
   pip install -r requirements.txt
   ```
4. **Run the notebook first** (or `train_models.py`) to generate the models and aggregate
   tables the dashboard depends on:
   - In PyCharm: open `Digital_Payments_Analysis.ipynb` and run all cells, **or**
   - From the terminal:
     ```bash
     python train_models.py
     ```
   This creates everything inside `data/agg_*.csv` and `models/*.pkl`.
5. **Run the dashboard**:
   - Right-click `app.py` → **Run 'app'**, or from the terminal:
     ```bash
     python app.py
     ```
6. Open **http://127.0.0.1:8050** in your browser.

## Dashboard Tabs

| Tab | What it shows |
|---|---|
| 📊 Trends | Monthly transaction volume & value, payment method and channel mix over time |
| 📅 Peak Seasons | Seasonality by calendar month, day of week, and hour of day; peak/lowest month callouts |
| 🔮 Forecast | RandomForest-based forecast of future monthly transaction volume (adjustable horizon, 1–12 months) |
| 💳 Channel Preference | Mobile/Digital vs Card/Bank share overall, by sector, and by customer segment |
| 🤖 ML Predictor | Interactive form — enter sector, segment, device, amount, day/hour → predicts the most likely payment channel and method |

## Machine Learning Models

1. **Forecast model** (`RandomForestRegressor`) — predicts next month(s) transaction count
   from time index, month-of-year, and lagged volume. R² ≈ 0.79 on historical fit.
2. **Channel preference model** (`RandomForestClassifier`) — predicts Mobile/Digital vs
   Card/Bank preference from sector, customer segment, device, amount, day/hour. Accuracy ≈ 60%
   (baseline ≈ 41%), so there is real, if modest, signal.
3. **Payment method model** (`RandomForestClassifier`) — predicts the specific method (Card,
   Digital_Wallet, QR_Payment, Virtual_Card, Cryptocurrency). Accuracy ≈ 21%, close to the
   5-class random baseline (20%) — the dataset's `Payment_Method` field doesn't correlate
   strongly with the other features available. This is reported in the dashboard itself so it
   isn't mistaken for a reliable prediction.

## Re-training

If you update `data/Digital_Payments_Data.csv`, just re-run `train_models.py` (or the notebook)
to regenerate the aggregates and models — the dashboard will pick up the new files on next launch.
